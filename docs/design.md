# 设计说明

本文记录实现时的关键取舍，方便二次开发。

## 为什么是应用层代理

平台是 TCP Client、设备是 TCP Server，两者之间的流量不经过监听电脑的网卡。要"看见"数据只有三条路：

1. **交换机端口镜像**：需要可管理交换机，且不能改数据；
2. **ARP 欺骗**：Windows 上要装 Npcap、自行维护 TCP 序列号，容易打断生产链路；
3. **应用层代理**：平台连监听程序，监听程序连设备，逐字节转发。

本项目选择第 3 条。它要求平台侧改一次目标 IP:端口，但换来的是双向可见、可解析、可落盘、可做超时控制，且不依赖网络设备能力。

## 进程与线程模型

```
┌──────────────────────────── 主进程 ────────────────────────────┐
│  asyncio 事件循环（主线程）                                     │
│    ├─ 平台 listener (asyncio.start_server)                      │
│    ├─ 设备链路（asyncio.open_connection + 读任务）               │
│    ├─ 每请求一个超时任务                                         │
│    └─ 心跳：每秒发布一次状态                                     │
│                                                                 │
│  ThreadingHTTPServer（独立线程，每连接一线程）                   │
│    ├─ 静态页面 / REST                                           │
│    └─ SSE：阻塞读 queue.Queue，超时发 ping                       │
└─────────────────────────────────────────────────────────────────┘
```

- 代理相关状态只在事件循环线程里修改，不需要锁；
- 网页线程通过 `asyncio.run_coroutine_threadsafe` 提交配置/启停操作；
- 事件通过线程安全队列推给 SSE 连接，队列满时丢最旧的 UI 事件（不阻塞代理）。

## 连接生命周期

**平台侧**：同一时刻只保留一个会话。新连接到达时接管旧连接（关闭旧 socket、取消其未完成请求），避免平台快速重连时被残留连接挡住。

**设备侧**状态机：

```
未连接 ──有平台数据──▶ 连接中 ──成功──▶ 已连接
   ▲                     │失败            │断开/EOF
   │                     ▼                ▼
   └──── 空闲超时 ◀── 已断开 ◀── 退避 0.5s→5s ──┘
```

- 设备链路由第一帧平台数据触发，避免平台没连时白占设备唯一的连接名额；
- 连接断开时，所有未完成请求都会被标记失败并记录；
- 平台断开后保留设备链路 `idle_close` 秒，减少设备侧反复建链；
- 连接和写入都显式设置 `TCP_NODELAY`，避免 Nagle 给轮询带来几十毫秒抖动。

## 分帧

Modbus TCP ADU 为 `MBAP(7B) + PDU`，其中 MBAP 的 Length 字段表示 `UID + PDU` 的字节数。`mbap.split_frames()` 负责从字节流中切出完整帧，处理半包、粘包和一次读到多帧。

帧头非法（PID≠0 或长度越界）时向后搜索下一个合法帧头并记录丢弃字节数；长时间无法同步（缓冲超过 4KB）则清空，避免内存膨胀。

首包不足 8 字节时无法判断协议，等下一批数据。若始终不符合 MBAP 特征（例如 RTU over TCP 设备），自动切换为 **raw 模式**：按读取块原样转发，只记录 HEX，不做解析——保证不会因为"认错协议"而中断通信。

## 解析

`mbap.decode(frame, direction, ref)` 返回结构化字段与中文摘要：

- 请求按 FC 解析地址、数量、写入值；应答优先使用对应请求的 `ref` 补全"0x0010–0x0013（4 个）"这类上下文；
- 写多寄存器会校验 `字节数 == 数量×2`，不一致时标记异常但仍转发；
- 地址显示支持 `address_offset`（0 或 1）；
- 未知功能码只展示 HEX，不视为错误。

**解析永远不影响转发**：`decode` 抛出的任何异常都在内部兜底为"解析失败"字段，字节流照旧转发。

## 超时与异常

每个请求发出后按 `TID` 登记 `{写出时间, 解析结果, 原始帧}` 并启动超时任务：

- 收到应答：按 TID 取出，计算 RTT = `收到时间 - 写出时间`，转发给平台；
- 超时：删除登记。
  - `timeout_policy=drop`：只记录，不打扰链路（默认，最透明）；
  - `timeout_policy=exception`：根据请求头构造 `FC|0x80 + 0x0B` 的异常应答代回平台，平台不会一直干等。

平台断开或新连接接管时，会取消该连接的所有超时任务并清理登记。

## 记录

- 每帧先写 `data.log` / `data.csv` 再转发；
- 默认逐条 flush（`record.flush=false` 可关，提升高帧率场景吞吐）；
- 按文件大小滚动，文件名追加 `_001`、`_002`；
- 启动时删除超过 `keep_days` 的日期目录；
- 磁盘剩余不足 100MB 时停止记录并告警，但**转发链路继续工作**；
- 记录内容为原始 ADU，解析结果是派生数据，可随时离线复算。

## 网页与背压

- 服务端保留最近 8000 条帧事件，刷新页面可回填；
- SSE 每个浏览器一个队列（上限 2000），满了丢最旧事件并计数；
- 前端最多保留 4000 条、渲染 800 行，超出滚动丢弃，避免长时间运行后浏览器卡顿；
- 页面暂停只停止渲染，记录与转发不受影响。

## 可靠性细节

| 问题 | 处理 |
| --- | --- |
| 设备半开连接 | 读任务 EOF 触发重建；写入 `drain` 超时 5s 也重建 |
| 平台不收数据 | 发送缓冲超过 4MB 时关闭该平台连接，防止内存膨胀 |
| 重复实例 | 启动时探测网页端口上是否已有实例，有则只打开浏览器 |
| 端口占用 | 监听失败在网页显示原因；网页端口占用自动顺延 10 个端口 |
| 程序异常 | 连接处理异常被隔离在单个会话内，不拖垮进程 |
| 目录不可写 | 自动退回到 `%LOCALAPPDATA%\ModbusMonitor` |

## 测试策略

- `tests/test_mbap.py`：分帧、重同步、各 FC 编解码、异常帧、地址偏移；
- `tests/test_proxy_e2e.py`：进程内启动假设备与真代理，覆盖读写、异常透传、设备不响应、平台接管、落盘校验；
- `tests/fake_*.py`：手工联调用的假设备/假平台；
- CI：GitHub Actions 在 Windows 上跑全部单元测试（Python 3.10 / 3.13）。

## 已知取舍

| 取舍 | 原因 |
| --- | --- |
| 只支持单平台连接 | 设备本身只允许一条 TCP；多客户端需要 TID 重映射与应答分发，复杂度高且现场少见 |
| TID 原样透传 | 单平台单连接下没有冲突；不改包也让行为最接近直连 |
| 只做 Modbus TCP | 目标场景明确；RTU over TCP 退化为 raw 转发 |
| 无认证 | 内网工具，鉴权会显著增加部署成本；README 已提示网络边界 |
